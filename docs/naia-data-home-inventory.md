# 데이터 홈(`~/.naia`)에 무엇이 남아 있나

## 규칙

`~/.naia` 에는 **`adk-path` 하나만** 있어야 한다. 나머지는 모두 그 파일이
가리키는 ADK 아래에 있어야 하고, 그 위치는 `adk-path` 에서 **파생**되어야
한다. 코드가 홈 디렉터리를 직접 짚으면 ADK 를 옮겼을 때 데이터가 따라가지
못한다 — 지금 상태로 ADK 를 옮기면 17GB 가 홈에 남는다.

(루크 지시 2026-09-05, 상위 계약 Scope 9 와 같은 내용.)

## 실측 (2026-09-05, naia-os-3090)

|---|---|---|---|

| `logs` | 138M | `lib.rs:1505` | ADK 로 가야 한다 |

| `run` | 124K | `lib.rs:1632` | ADK 로 가야 한다 |
| `apps` | 0 | `app.rs:115` | ADK 로 가야 한다 |

손으로 세었을 때는 다섯이었는데, 검사기를 만들어 돌리니 **열셋**이었다.
파일 시스템에 아직 나타나지 않은 것들이 더 있었다.

| 이름 | 만드는 파일 | 옮길 때 함께 풀 것 |
|---|---|---|
| `panels` | `app.rs` | |
| `chrome-profile` | `browser.rs` | 사용자의 로그인 상태가 들어 있다 — 옮기면 다시 로그인해야 한다 |
| `login-profile` | `browser.rs` | 위와 같다 |
| `.naia` (직접) | `lib.rs` | 데이터 홈 함수를 거치지 않아 `NAIA_HOME` 도 무시한다. 격리된 개발 인스턴스가 운영 데이터를 건드릴 수 있다 |
| `deep-link-pending.txt` | `platform/macos.rs`, `platform/windows.rs` | 앱이 뜨기 전에 쓰이므로 ADK 위치를 아직 모를 수 있다 — 순서를 함께 풀어야 한다 |
| `dev-deeplink` | `platform/macos.rs` | 위와 같다 |

Rust 에서 데이터 홈을 쓰는 자리는 열여덟 곳이다.

`credentials` 와 `memory` 는 **이미 ADK 아래를 쓰도록 고쳐져 있다**
(`lib.rs:11132`, `memory.rs:315` 가 `naia-settings` 아래를 짚는다). 홈에 있는
같은 이름의 디렉터리는 그 전에 만들어진 잔재다. 즉 옮기는 일의 일부는 이미
끝나 있고, 남은 것은 위 표에서 "만드는 자리"가 홈을 짚는 다섯이다.

## 옮길 때 조심할 것

`voxcpm2-runtime` 17GB 는 이 기계의 음성 서비스가 지금 쓰고 있다. 옮기는 것은
서비스 중단을 동반하므로 사람이 창을 잡아야 한다. 상위 계약도 이번 작업에서는
옮기지 말고 목록과 목표만 남기라고 되어 있다.

## 새로 생기는 것을 막는다

`scripts/check-data-home-boundary.mjs` 가 데이터 홈 아래에 `adk-path` 말고
다른 경로를 새로 만드는 코드를 막는다. 오늘의 다섯 자리는 사유와 함께 적어
두었고, 옮기고 나면 그 항목을 지우면 된다. 목록이 낡으면(그 자리가 없어졌는데
목록에 남아 있으면) 그것도 붉어진다.
