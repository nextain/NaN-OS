# 품질 프로세스

0.2.3 기준. 이 문서는 "무엇이 되는가" 를 넘어 "쓸 만한가" 를 어떻게 재는지,
그리고 배포 전에 무엇을 확인하고 나가는지를 정한다.

## 왜 이 문서가 필요했나

테스트는 두껍다. 단위·계약 1934건이 돌고, 실기 스펙이 130개, Playwright 가
64개, Rust 가 285개다. 그런데 리눅스에서 로컬 음성이 설치에 실패하고도 조용히
브라우저 음성으로 넘어간 결함이 넉 달을 살았다.

이유를 따라가 보면 테스트가 없어서가 아니었다. 그것을 잡을 스펙은 있었다
(`96-voice-linux-app-start.spec.ts`). **아무 데서도 돌지 않았을 뿐이다.**

같은 성격의 것이 더 있었다. UC 추적 게이트는 옛 이름 체계만 보도록 굳어
현재 표제 예순다섯 개를 하나도 세지 못한 채 초록을 보고했다. 어떤 스펙은
`expect(true).toBe(true)` 하나로 통과를 보고하면서 화면은 아무것도 보지
않았다. 숫자는 늘었지만 그 숫자가 무엇을 보증하는지가 흐려져 있었다.

그래서 이 문서가 정하는 것은 새 테스트를 더 만드는 방법이 아니라, **있는
것이 실제로 돌고 거짓말하지 않게 하는 절차**다.

## 층

네 층으로 나눈다. 위로 갈수록 느리고 비싸며, 아래에서 잡을 수 있는 것을
위에서 잡지 않는다.

**1층 단위·계약.** 함수와 모듈이 계약대로 도는가. vitest 와 Rust 단위
테스트가 여기다. 사람의 개입도 외부 자원도 없어야 하고, 실패하면 어느 줄이
잘못인지 바로 나와야 한다. 지금 1934 + 285건.

**2층 통합.** 모듈이 서로 맞물리는가. 실제 파일 시스템, 실제 프로세스,
실제 포트를 쓰되 사람 손은 없다. `lib.rs` 의 포트 회수 테스트처럼 진짜
리스너를 띄워 확인하는 것이 여기다.

**3층 실기.** 사용자가 만지는 것과 같은 앱에서 도는가. `e2e-tauri` 130개와
Playwright 64개가 여기다. 느리고 환경을 탄다.

**4층 회귀.** 배포 전에 3층 전체를 한 번 돌린다. 한 기계에서 다 돌 수 없으므로
나눈다. 아래 "여러 기계로 나누기" 를 보라.

## 품질 기준

기능이 되는지는 1~3층이 본다. 이 절은 그 위에서 무엇을 더 보는지를 정한다.
셋 다 **결정론으로 재는 것만** 넣는다. 사람의 감이 필요한 것은 이 기준에
넣지 않는다 — 넣으면 판정이 흔들리고 곧 꺼진다.

### 사용성

무엇을 재는가: 실패했을 때 화면이 다음에 무엇을 하라고 말하는가, 되돌릴 수
있는가.

주의할 것이 있다. **화면 문구로 재는 것은 이 저장소에서 아직 위험하다.**
로케일이 열넷인데 `.tsx` 에 하드코딩된 한국어가 830줄 있고, 그래서 기존
단정이 `getByText("다시 시도")` 같은 취약한 쪽과 `/다시 시도|try again/i`
같은 아무것도 보증하지 않는 쪽으로 갈려 있다. 후자는 나머지 열두 언어에서
무엇이 보이는지 전혀 말하지 않는다.

그러므로 사용성은 **문구가 아니라 i18n 키로** 잰다. 화면이 어떤 키를
해석해 보여주는지를 확인하면 언어에 관계없이 같은 판정이 선다. 하드코딩
한국어를 키로 옮기는 것이 그 선행 작업이며, 그 전까지 이 축은 열려 있다.

### 안정성

무엇을 재는가: 재시작 뒤 상태가 남는가, 동시에 만졌을 때 깨지는가, 의존이
죽었을 때 무엇이 보이는가.

이 축은 이미 상당히 덮여 있다. 세션 복원 8건, 포트 경합 회수가 실제 리스너로
검증된다. 남은 공백은 동시성이다 — 실제로 경쟁시키는 테스트가 손에 꼽는다.

### 성능

무엇을 재는가: 크기와 시간.

크기는 이미 한도가 있다. `packages/shell/bundle-budget.json` 이 진입 스크립트
원본 500KB, gzip 160KB, 배포본 170MB 를 정하고 CI 가 넘으면 실패시킨다.

**시간은 한도가 없다.** 첫 응답까지, 발화가 시작되기까지, 앱이 뜨기까지를
단정하는 곳이 없다. 지금은 타임아웃이 사실상의 한도인데, 그것은 "안 죽었다"
만 말한다. 이 축을 채울 때는 값이 아니라 **한도**를 정하고 넘으면 실패로
본다. 측정값을 기록만 하는 것은 아무것도 막지 못한다.

## 여러 기계로 나누기

3층은 한 기계에서 다 돌 수 없다. 요구 조건이 다르기 때문이다.
`scripts/build-e2e-inventory.mjs` 가 스펙마다 무엇을 요구하는지 뽑아
`docs/e2e-inventory.json` 에 남긴다. 등급은 사람이 붙이지 않고 요구 조건에서
기계로 정한다 — 사람이 붙인 꼬리표는 곧 낡는다.

| 등급 | 뜻 | 현재 수 |
|---|---|---|
| ci | 추가 자격증명도 장치도 필요 없다 | 104 |
| keyed | 외부 자격증명이 필요하다 | 23 |
| device | 그 기계의 장치가 필요하다(GPU·오디오·데스크톱 세션) | 3 |

`ci` 라도 Tauri 실행 환경(WebKitWebDriver, tauri-driver, 빌드된 디버그
바이너리)은 공통 전제다. "환경 변수를 요구하지 않는다" 가 "아무 데서나
돈다" 는 뜻은 아니다.

기계별로 이렇게 나눈다.

- **러너**: 1층 전부, 2층 전부, 3층의 Playwright 64개. 지금 CI 가 하는 일이다
- **리눅스 실기(GPU 있는 개발 기계)**: `device` 등급, 그리고 리눅스 전용 음성
  경로. 다만 이 기계의 WebKitWebDriver 는 일부 스펙에서 앱 준비 단계를 넘지
  못한다(`e2e-tauri/helpers/settings.ts:404` 의 기록, 2026-09-05 재확인)
- **Windows 실기**: `keyed` 와 `ci` 등급의 실기 스펙. 위 제약이 없는 쪽이다

## 회귀를 나눠 돌리는 법

기계마다 자기 몫을 돌리고 기록을 남긴다.

```
node scripts/run-regression.mjs --machine=<이름> --tier=ci[,keyed,device]
node scripts/run-regression.mjs --machine=<이름> --tier=ci --dry-run
```

`--dry-run` 은 무엇을 돌릴지와 **환경이 없어 건너뛸 것이 무엇인지** 만
보여준다. 환경을 갖추기 전에 먼저 본다.

배포 전에는 기록을 모아 빈 곳을 찾는다.

```
node scripts/check-regression-complete.mjs --max-age-hours=24
```

아무도 맡지 않은 스펙이 있거나, 건너뛴 것이 있거나, 실패한 기계가 있으면
통과하지 않는다.

## 배포 전에 확인하는 것

순서대로 본다. 앞이 붉으면 뒤로 가지 않는다.

1. 1층과 2층이 초록이다(종료 코드로 확인한다. 통과 개수로 확인하지 않는다)
2. 게이트가 초록이다 — 아래 "게이트" 절
3. 3층을 기계별로 나눠 돌리고, 각 기계가 결과를 남긴다
4. 돌지 않은 스펙이 몇 개인지 센다. **돌지 않은 것을 통과로 세지 않는다**
5. 크기 예산을 넘지 않는다

## 게이트

숫자가 거짓말하지 않게 하는 장치들이다. 전부 CI 에서 돌고, 결정론이며,
LLM 을 부르지 않는다.

| 게이트 | 무엇을 막는가 |
|---|---|
| `check-uc-traceability.mjs` | UC 가 어디서 검증되는지 아무 데도 적히지 않은 채 늘어나는 것 |
| `check-vacuous-tests.mjs` | 아무것도 재지 않는 통과와 이유 없이 꺼 둔 테스트가 늘어나는 것 |
| `check-bundle-budget.mjs` | 진입 번들과 배포본이 정한 크기를 넘는 것 |
| `check-untranslated-ui.mjs` | 화면에 박힌 한국어가 늘어나는 것 — 사용성 축을 i18n 키로 재기 위한 선행 |
| `build-e2e-inventory.mjs --check` | 실기 스펙 요구조건 목록이 실제 스펙과 어긋난 채 남는 것 |
| `check-assembly-coverage.mjs` | (옛 이름 체계 전용 — 위 UC 게이트가 지금 체계를 맡는다) |

앞의 두 게이트는 지금 상태를 baseline 으로 고정하고 늘어나는 것만 막는다.
한 번에 붉히면 CI 가 막히고 게이트는 곧 꺼지기 때문이다. **줄이면 baseline 도
함께 줄여야 한다** — 늘리기만 하면 baseline 이 알리바이가 된다.

## 지금 열려 있는 것

이 문서가 정한 것 중 아직 안 된 것을 숨기지 않고 적는다.

1. **3층이 CI 에서 하나도 돌지 않는다.** `e2e-tauri` 130개를 부르는 워크플로가
   없다(#550)
2. ~~시간 한도가 없다~~ → 시작 지연 한도 하나를 걸었다
   (`UC-PERF-STARTUP-LATENCY`, 한도 2,000ms). 첫 응답까지와 발화 시작까지는
   아직 없다
3. **사용성 축이 열려 있다.** 화면에 박힌 한국어가 435줄(38파일) 남아 있고,
   이것을 i18n 키로 옮기기 전에는 문구 판정이 거짓 통과를 만든다.
   `check-untranslated-ui.mjs` 가 늘어나는 것만 막고 있다 — 줄이는 것은 아직
   시작하지 않았다
4. **UC 열한 개가 추적에서 끊겨 있다.** 검증이 없다는 뜻이 아니라 어디서
   검증되는지 적혀 있지 않다는 뜻이다
5. **아무것도 재지 않는 스펙 두 개와 이유 없이 꺼 둔 테스트 열여섯 개**가
   남아 있다
