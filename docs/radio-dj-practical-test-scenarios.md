# Radio DJ 실기 테스트 시나리오

> 작성일: 2026-08-04
> 대상: naia-shell `Youtube Radio DJ`
> 목적: 단순 대기열 연속 재생이 아니라, 실제 YouTube 환경에서 자율 선곡·DJ 멘트·사용자 개입·취향 기억·중복 회피·즐겨찾기·재생 불가 복구가 함께 동작하는지 검증한다.

## 1. 제품 완료선

Radio DJ의 기본 흐름은 다음과 같다.

1. 현재 곡의 실제 `playing`과 진행 위치를 관측한다.
2. 현재 곡의 실제 `ended`를 한 번만 처리한다.
3. 짧은 DJ 멘트를 한다.
4. 최근 재생·싫어요·실패 후보를 제외하고 비슷한 새 곡을 동적으로 찾아 재생한다.
5. 다음 곡의 실제 `playing`을 확인한 뒤에만 제목·아티스트를 소개한다.
6. 사용자의 대화·곡 교체·정지 명령은 모든 자동 행동보다 우선한다.

종료 전 다음 후보를 미리 찾는 prefetch는 무음을 줄이는 후속 개선이다. 현재 완료선은 사용자 요청대로 `ended` → 짧은 멘트 → fresh 동적 검색 순서를 보장하며, 재생과 소개를 새 곡의 상관된 관측 결과에 결속한다.

## 2. 현재 기준선과 알려진 공백

2026-08-05 현재 확인된 범위는 다음과 같다.

- 구현·자동 검증됨: 요청과 실제 재생 관측 분리, `currentTime/duration`, 오래된 `playbackId` 격리, 중복 `ended` 방어, 대기열 순서, 동일 영상 재시도 시 새 iframe, 오류·15초 로딩 시간초과 뒤 준비 후보 전환, 첫 재생 실패 뒤 Agent의 제한된 새 선곡, 최근·실패·정규화 중복 후보 제외, 일반 대화 중 재생 유지, 명시적 곡 교체, 정지 뒤 늦은 전환 차단, 즐겨찾기 등록·재생·삭제·빈 목록.
- paired Agent 자동 검증됨: 모든 play의 `mode=radio_dj`, 실제 `ended` → 짧은 전환 멘트 → fresh 동적 선곡 → 상관된 `playing` 뒤 소개, 태그된 사용자 취향의 naia-memory recall, local tombstone 우선, bounded 최근곡·즐겨찾기 결합, 기억 장애 축소 동작.
- 멀티모달 전달 계약: bounded PNG/JPEG/WebP inline image를 도구 결과와 상관시키고 OpenAI·Anthropic·Ollama 입력으로 전달한다. Shell 음악 표면 캡처 생성은 아직 연결하지 않았다.
- 남은 물리 환경 증거: 종료 전 다음 곡 prefetch, 실제 음성으로 즐겨찾기 관리, 음악 표면 전용 캡처, 절전·복귀, 네트워크 단절·복구, 실제 YouTube 길이 혼합 20곡 세션. 이 항목은 자동 계약 통과로 대체해 기록하지 않는다.

10곡 Playwright의 기본 실행은 `duration=3600` 메타데이터를 사용하는 압축 테스트다. 2026-08-05에는 `RADIO_DJ_LONG_TRACK_MS=3600000`으로 첫 로컬 fixture를 실제 벽시계 60분 재생하고 나머지 9곡까지 순서대로 전환하는 실행을 통과했다. 같은 실행군의 60곡·곡당 논리 8분 fixture는 15곡 시점의 2시간과 전체 8시간 media clock, 고유 playback 60개, 최근 이력 20개 상한을 약 13초에 통과했다. 전자는 실제 수명·전환 증거이지만 외부 YouTube가 아니며, 후자는 L4 시간 가속 증거다.

실제 YouTube opt-in smoke에서는 sidecar 검색으로 11:58:09 장곡 `lh4JdZTJe7k`를 선택하고 `youtube-nocookie` 실제 embed가 HTTP 200, `readyState=4`, media 오류 없음으로 재생되는지 관측했다. 30초와 10분 관측에 이어 실제 벽시계 8시간 soak를 통과했다. 2시간 체크포인트의 media clock은 7,203.0초, 최종값은 28,800.6초였고 페이지·미디어 오류는 없었다. 이는 RD-LONG-01의 실제 장곡 수명과 8시간 운용 증거이지만 실제 길이 혼합 20곡 세션은 아니다.

같은 날 paired naia-agent 정본 커밋과 proto 해시를 사용한 Linux Tauri/WebKitGTK 격리 E2E에서 소유 BGM sidecar 기동과 관측된 A `ended` 뒤 B 전환 2건을 통과했다.

## 3. 검증 계층

| 계층 | 환경 | 판정 목적 |
|---|---|---|
| **L1 결정론적 Playwright** | 로컬 iframe·검색·Tauri 이벤트 fixture | 순서, 경쟁 조건, 중복 이벤트, 사용자 명령, 메모리 영수증을 빠르게 재현 |
| **L2 네이티브 Tauri** | 실제 WebView + 로컬 fixture | Rust IPC, 창 수명, 실제 TTS 취소, 앱 재시작과 저장 복원 |
| **L3 실제 YouTube 실기** | 실제 검색·iframe·네트워크 | 영상 길이 편차, 광고·임베드 제한·삭제 영상·네트워크 지연 대응 |
| **L4 장시간 운용** | 실제 또는 충실한 시간 가속 fixture | 2시간/8시간 동안 누적 누수, 반복 추천, 대기열·리스너·타이머 수명 검증 |

L1 통과를 L3/L4 통과로 표현하지 않는다. 실제 YouTube의 결과 자체는 결정론적 CI 게이트가 아니지만, 릴리스 전 실기 보고서에는 사용한 영상·시간·오류·대체 결과를 남긴다.

## 4. 공통 관측 증거

각 실행은 최소한 다음 정보를 타임라인으로 남긴다.

- 사용자 입력, agent의 도구 호출과 결과, 검색어와 후보 순위
- `playbackId`, `videoId`, 정규화한 곡 키(제목+아티스트), 상태, `currentTime/duration`
- 종료 임박 검색 시각, `ended` 시각, DJ TTS 시작·취소·종료, 다음 곡 `playing` 시각
- 최근 재생 제외 목록, 좋아요·싫어요·즐겨찾기·실패 목록의 사용 여부
- 메모리 쓰기·읽기·삭제 영수증과 저장 범위(세션/장기)
- iframe·이벤트 리스너·타이머·대기열 크기, 브라우저/Agent 오류

오디오가 들렸다는 사람의 인상만으로 합격시키지 않는다. 화면 상태, 이벤트, 검색·메모리 영수증 중 두 종류 이상의 객관 증거를 함께 남긴다.

## 5. 실기 시나리오

### A. 실제 길이와 연속 재생

| ID | 실기 절차 | 합격 기준 | 계층 |
|---|---|---|---|
| **RD-LONG-01 실제 긴 곡** | 12분 이상 실제 영상을 한 곡 재생하고 1초 간격으로 관측한다. | 실제 벽시계 기준 10분 이상 `playing`이 신선하게 유지되고 iframe 재생성·가짜 종료·중복 멘트가 없다. | L3 |
| **RD-LONG-02 길이 혼합 2시간** | 1~3분, 4~8분, 10분 이상 영상을 섞어 최소 20곡을 재생한다. | 각 전환은 실제 `ended` 이후 한 번만 발생하고, 누락·건너뜀·고정 길이 가정이 없다. | L3/L4 |
| **RD-LONG-03 중복·지연 종료** | A 종료를 두 번 보내고 B 재생 뒤 A의 늦은 종료·오류를 보낸다. | A 이벤트가 B를 멈추거나 C로 건너뛰게 하지 않는다. | L1/L2 |
| **RD-LONG-04 절전·복귀** | 재생 중 PC 화면 잠금 또는 절전 후 복귀한다. | 현재 관측을 재확인하고, 불명 상태를 `playing`으로 추정하지 않으며 중복 player/controller를 만들지 않는다. | L2/L3 |

### B. 곡 종료, DJ 멘트와 동적 선곡

| ID | 실기 절차 | 합격 기준 | 계층 |
|---|---|---|---|
| **RD-DJ-01 종료 후 한마디** | 곡 A를 끝까지 재생한다. | A의 `ended`를 확인한 뒤 짧은 멘트가 정확히 한 번 나오고, A가 재생 중인 것처럼 말하지 않는다. | L1/L2/L3 |
| **RD-DJ-02 다음 곡 동적 검색** | A의 `ended` 뒤 짧은 멘트를 완료하고 새 검색 응답을 기다린다. | 멘트 전 검색·B 재생이 시작되지 않고, fresh 후보 B만 요청한다. B 소개는 상관된 `playing` 뒤 발생한다. 종료 전 prefetch는 별도 지연 개선으로 측정한다. | L1/L3 |
| **RD-DJ-03 새 곡 관측 후 소개** | B 요청 성공 뒤 iframe의 `playing`을 지연시킨다. | 요청 성공만으로 B를 소개하지 않고 실제 `playing` 뒤 한 번만 소개한다. | L1/L2 |
| **RD-DJ-04 검색 지연** | 다음 곡 검색 응답을 15초 지연시킨다. | 반복 멘트나 동일 요청 폭주 없이 한 번 기다리고, 사용자에게 거짓 재생 성공을 말하지 않는다. | L1/L3 |

| **RD-USER-06 정지** | “라디오 그만”이라고 한다. | 음악·DJ TTS·다음 곡 검색·예약 타이머를 모두 종료하고 이후 자동 호출이 0회다. | L1/L2/L3 |

### D. 취향 기억과 개인정보 경계

장기 취향은 사용자의 명시적 표현만 저장한다. 단순히 끝까지 들음, 오래 들음, 건너뜀 한 번, 일반 대화의 감정 표현을 영구 취향으로 추론하지 않는다.

| ID | 실기 절차 | 합격 기준 | 계층 |
|---|---|---|---|
| **RD-MEM-01 좋아요 기억** | “이 곡 좋아”, “이런 재즈 좋아해”라고 말하고 앱을 재시작한다. | 곡/아티스트/장르 또는 분위기와 명시적 선호 근거가 장기기억에 남고 다음 세션 추천에 반영된다. 쓰기·재호출 영수증이 있다. | L1/L2 |
| **RD-MEM-02 싫어요 기억** | “이 곡과 이 아티스트는 싫어”라고 한다. | 범위를 구분해 저장하고 이후 자동 추천에서 제외한다. 사용자의 직접 재생 요청은 확인 후 실행할 수 있다. | L1/L2/L3 |
| **RD-MEM-03 과잉 추론 금지** | 곡을 끝까지 듣거나 한 번 건너뛰되 취향 표현은 하지 않는다. | 장기 취향 쓰기가 0회다. 이력은 세션 중 중복 회피에만 사용한다. | L1/L2 |
| **RD-MEM-04 조회·수정·삭제** | “내 음악 취향 알려줘”, “재즈 싫다는 기억 지워줘”, “DJ 취향 전부 삭제해”를 차례로 실행한다. | 저장 내용을 사람이 이해할 수 있게 보여주고 지정 범위만 수정·삭제한다. 삭제 후 재시작해도 복원되지 않는다. | L1/L2 |
| **RD-MEM-05 기억 장애** | 메모리 읽기·쓰기를 실패시킨다. | 개인화 성공을 가장하지 않고 세션 내 최근곡만 사용한다. 재생 자체는 가능하면 계속하고 비밀·원문 대화를 로그에 남기지 않는다. | L1/L2 |
| **RD-MEM-06 사용자 격리** | 서로 다른 두 계정에서 반대 취향을 저장한다. | 계정 간 취향·즐겨찾기·최근 이력이 섞이지 않는다. | L2 |

### E. 반복 방지와 비슷한 새 곡 추천

초기 수용 기준은 다음과 같다. 실제 카탈로그가 부족하거나 사용자가 명시적으로 같은 곡을 요청한 경우에만 예외를 허용하고 그 이유를 기록한다.

- 같은 `videoId` 또는 정규화한 같은 곡(제목+아티스트)은 최근 20곡 또는 현재 6시간 세션 중 더 넓은 범위에서 자동 재추천하지 않는다.
- 동일 음원의 가사 영상·공식 영상·재업로드처럼 영상 ID만 다른 중복도 같은 곡으로 취급한다.
- 같은 아티스트는 연속 추천하지 않고, 자동 선곡 10곡 중 최대 2곡을 기본 상한으로 한다.
- 비슷함은 사용자가 요청한 장르·분위기·에너지·시대 중 근거가 있는 축을 유지하되, 제목이나 검색 결과 1위만 반복하지 않는다.

| ID | 실기 절차 | 합격 기준 | 계층 |
|---|---|---|---|
| **RD-VAR-01 같은 영상 제외** | 검색 결과 1위가 현재 또는 최근 `videoId`가 되게 한다. | 다음의 미재생 후보를 선택하고, 대안이 없으면 같은 곡을 조용히 반복하지 않는다. | L1/L3 |
| **RD-VAR-02 동일 음원 다른 영상** | 같은 곡의 공식·가사·재업로드 영상을 후보에 섞는다. | 정규화 곡 키로 하나의 곡으로 판단해 최근곡이면 모두 제외한다. | L1/L3 |
| **RD-VAR-03 비슷하지만 새로운 곡** | “지금 곡과 비슷한 분위기로 계속”이라고 한다. | 장르·분위기는 유지하면서 최근 곡·싫어요를 제외한 다른 곡을 선택하고 선택 근거를 기록한다. | L1/L3 |
| **RD-VAR-04 아티스트 편중** | 검색 상위 10개 중 7개를 같은 아티스트로 구성한다. | 연속 동일 아티스트를 피하고 10곡당 기본 상한을 지킨다. | L1 |
| **RD-VAR-05 장시간 피로도** | 8시간 상당으로 최소 60회 선곡한다. | 정책 밖 동일 곡 반복 0회, 반복 아티스트 상한 준수, 제외 목록과 메모리 사용량이 유한하게 유지된다. | L4 |

### F. 즐겨찾기

| ID | 실기 절차 | 합격 기준 | 계층 |
|---|---|---|---|
| **RD-FAV-01 현재 곡 등록** | 재생 중 “이 곡 즐겨찾기에 등록해줘”라고 한다. | 현재 관측된 곡을 정확히 한 번 저장하고 제목·영상 ID를 확인한다. 같은 명령 반복은 중복 항목을 만들지 않는다. | L1/L2/L3 |
| **RD-FAV-02 등록 취소** | “이 곡 즐겨찾기에서 빼줘”라고 한다. | 해당 곡만 제거되고 재시작 뒤에도 제거 상태가 유지된다. | L1/L2 |
| **RD-FAV-03 즐겨찾기 재생** | “내 즐겨찾기 틀어줘”라고 한다. | 즐겨찾기만을 후보로 사용하고, 한 바퀴를 돌기 전 같은 곡을 반복하지 않는다. 실제 `playing` 뒤에만 재생 성공을 말한다. | L1/L2/L3 |
| **RD-FAV-04 빈 목록** | 즐겨찾기를 비운 뒤 재생을 요청한다. | 비어 있음을 정확히 알리고 일반 추천으로 바꿀지 묻거나 명시 정책에 따라 한 번만 전환한다. 임의의 즐겨찾기를 꾸며내지 않는다. | L1/L2 |
| **RD-FAV-05 재생 불가 즐겨찾기** | 즐겨찾기 하나를 임베드 불가로 만든다. | 실패 항목은 즐겨찾기에서 자동 삭제하지 않지만 이번 재생에서는 건너뛰고 다음 즐겨찾기를 시도한다. | L1/L3 |

### G. 재생할 수 없는 곡과 장애 복구

| ID | 실기 절차 | 합격 기준 | 계층 |
|---|---|---|---|
| **RD-ERR-01 임베드 불가** | YouTube가 “재생할 수 없는 곡입니다” 또는 iframe `onError`를 반환하게 한다. | `playing`으로 보고하거나 곡을 소개하지 않는다. 후보를 세션 실패 목록에 넣고 다른 곡을 검색한다. | L1/L3 |
| **RD-ERR-02 삭제·지역·연령 제한** | 삭제, 지역 제한, 연령 제한 후보를 각각 재현한다. | 가능한 오류 분류를 남기고 같은 후보·동일 음원의 재업로드를 무한 반복하지 않는다. | L1/L3 |
| **RD-ERR-03 대체곡 연속 실패** | 검색 후보 3개를 연속 실패시킨다. | 후보별 최대 1회만 시도하고 제한된 횟수 뒤 짧게 알리거나 사용자 선택을 기다린다. 무한 검색·TTS 반복이 없다. | L1/L3 |
| **RD-ERR-04 네트워크 단절·복구** | 재생 중 네트워크를 끊었다가 복구한다. | 상태를 오류/불명으로 전환하고 성공을 가장하지 않는다. 복구 뒤 현재 곡 재관측 또는 새 후보 검색을 한 번만 수행한다. | L2/L3 |
| **RD-ERR-05 sidecar 재시작** | 검색 사이드카를 종료한 뒤 다음 곡을 요청한다. | 소유한 sidecar를 한 번 재기동해 검색을 복구하며 중복 프로세스를 만들지 않는다. | L2 |

## 7. 합격 보고서 형식

각 실행 보고서는 다음 항목을 포함한다.

1. 빌드·Shell·paired agent 커밋
2. 계층(L1~L4), OS, WebView, 계정·메모리 격리 방식
3. 시작·종료 시각과 실제 운용 시간
4. 수행한 시나리오 ID와 PASS/FAIL/BLOCKED
5. 재생곡·실패 후보·중복 제외·대체곡 타임라인
6. 사용자 개입과 TTS 취소 지연
7. 취향·즐겨찾기 메모리 쓰기/읽기/삭제 증거
8. 오류·로그·스크린샷 또는 영상
9. 남은 외부 경계와 재현 방법

`duration` 메타데이터만 길게 설정한 압축 테스트는 실제 장시간 운용 시간으로 기록하지 않는다.

> **Required negative precondition (2026-08-06):** Before every positive Radio
> DJ scenario, verify that cold boot, saved-song restore and Proactive ON/OFF do
> not emit play or start a DJ session. Positive scenarios must begin with an
> explicit user play or structured `skill_youtube_bgm(action=play,
> mode=radio_dj)` event. A transition without that authority fails the test.
