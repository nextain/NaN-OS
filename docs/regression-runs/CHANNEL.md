# 회귀 QA 채널 규약

여러 기계가 나눠 도는 회귀는 서로의 상태를 봐야 한다. 기록 파일은 커밋한 뒤에야
보이고, 그 사이 다른 기계는 상대가 돌고 있는지 막혔는지 알 수 없다. 채널은 그
간격을 메운다.

## 말머리

모든 메시지는 대괄호 안의 기계 이름으로 시작한다. 이름은
`machines.json` 에 적힌 것과 **글자까지 같아야** 한다 — 다르면 사람은 알아보지만
기록과 대조할 수 없다.

```
[naia-os-3090] ...
[win-rtx4060] ...
[master] ...
```

`master` 는 취합하는 자리다. 지금은 `naia-os-3090` 이 겸한다.

## 상태 낱말

말머리 다음에 상태를 하나 적는다. 다섯 가지뿐이다.

| 낱말 | 뜻 | 누가 |
|---|---|---|
| `START` | 지금 무엇을 몇 개 돌리기 시작했다 | 각 기계 |
| `DONE` | 끝났다. 몇 개 중 몇 개가 통과했고 무엇이 실패했다 | 각 기계 |
| `BLOCKED` | 전제가 없어 시작하지 못했다. 무엇이 없는지 | 각 기계 |
| `ASK` | 사람의 판단이 필요하다 | 누구든 |
| `STATE` | 지금 전체가 얼마나 덮였는지 | master |

`DONE` 은 통과했다는 뜻이 아니라 **끝났다**는 뜻이다. 실패도 `DONE` 으로
알린다 — 실패를 알리지 않고 조용히 있으면 다른 기계가 기다린다.

## 형식

한 줄로 적는다. 긴 로그는 붙이지 않는다 — 채널은 상태를 나누는 자리이지 로그를
쌓는 자리가 아니다. 자세한 것은 커밋된 기록 파일에 있다.

```
[win-rtx4060] START deterministic_ci 14개 · 짝 bc468a17 · 산출물 D:\naia-e2e
[win-rtx4060] DONE 12/14 통과 · 실패 92-browser-app-clicks, 100-herdr-first-frame
[naia-os-bc250] BLOCKED 짝 naia-agent 체크아웃 없음 — NAIA_AGENT_WORKTREES_DIR 필요
[master] STATE 123개 중 덮인 것 26 · 아무도 맡지 않은 것 97 · 실패한 기계 없음
[win-nogpu] ASK 92번이 이 기계에서만 실패한다 — GPU 없는 경로의 결함인지 봐 달라
```

`START` 와 `DONE` 한 줄은 러너가 만들어 준다. 실행이 끝나면 화면 마지막에
그대로 복사할 수 있는 형태로 나온다.

## 마스터가 하는 일

1. 명단(`machines.json`)에 누가 활성인지 정하고 채널에 알린다
2. 각 기계의 `DONE` 을 모아 `STATE` 를 낸다
3. **실패가 회귀인지 기계 능력인지 가른다** — 같은 스펙이 여러 기계에서
   실패하면 회귀이고, 한 기계에서만 실패하면 그 기계의 환경일 가능성이 크다.
   이 판정은 여러 기계의 결과를 다 본 자리에서만 할 수 있다
4. 덮이지 않은 몫이 남으면 어느 기계가 집을지 정한다

## 하지 않는 것

- 채널 메시지로 서로의 저장소를 고치지 않는다. 코드 변경은 커밋과 이슈로 한다
- 자격증명, 토큰, 키를 적지 않는다. 무엇이 없는지만 적는다
  (`BLOCKED GEMINI_API_KEY 없음` 은 되고, 키 값은 안 된다)
- 실패 로그 전문을 붙이지 않는다. 스펙 이름과 한 줄 사유까지다
