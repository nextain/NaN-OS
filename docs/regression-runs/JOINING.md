# 회귀 QA 기계로 합류하기

런칭 전 회귀는 여러 기계가 나눠 돈다. 이 문서는 새 기계가 그 명단에 들어와
첫 기록을 남기기까지의 절차다.

## 1. 명단에 이름과 능력을 적는다

`machines.json` 에 항목을 더하거나, 이미 있으면 `active` 를 `true` 로 바꾼다.

명단에 없는 기계가 도는 것은 아무도 모르는 실행이다. 반대로 명단에 있으면서
돌지 않는 기계가 있으면 그 몫이 비고, 완결성 판정이 "아무도 맡지 않았다" 로
정직하게 붉어진다. 그래서 아직 합류하지 않은 기계는 `active: false` 로 둔다.

능력은 사실대로 적는다. GPU 가 없는 기계에 장치가 필요한 등급을 주면 실패가
쌓이는데, 그것은 회귀가 아니라 그 기계가 못 하는 일이다.

### 이름은 기계를 가리켜야 한다

명단의 이름은 사람이 짓지만, 그 이름이 이 기계가 맞는지는 러너가 확인한다.
호스트명과 운영체제가 명단과 어긋나면 **실행 전에** 거절한다.

이 방어는 실제 사고에서 나왔다. 회귀를 처음 돌릴 때 호스트명으로 이름을
지었다가 명단을 만들며 능력으로 다시 지었는데, 바뀌었다는 사실이 어디에도
없어서 같은 기계의 기록이 "모르는 기계" 로 보였다. 판정하는 쪽도 사람도
헷갈렸고, 채널에 잘못된 보고가 올라갔다.

이름을 바꿔야 하면 명단의 `formerNames` 에 옛 이름을 적는다. 그러면 옛 기록을
만나도 "같은 기계의 옛 이름" 이라고 말해 준다.

## 2. 전제를 갖춘다

| 전제 | 확인 |
|---|---|
| 짝 naia-agent 체크아웃 | 핀 커밋과 같고 작업 트리가 깨끗해야 한다. **모든** 스펙이 이것을 요구한다 |
| 디버그 바이너리 | `pnpm -C packages/shell run build:e2e:tauri` |
| `tauri-driver` | `cargo install tauri-driver` |
| 웹뷰 드라이버 | 리눅스는 `WebKitWebDriver`. 윈도우는 Edge WebView2 드라이버를 tauri-driver 가 찾는다 |
| 산출물 디렉터리 | `NAIA_E2E_ARTIFACTS_DIR` 로 쓰기 가능한 자리를 준다 |

짝 체크아웃 자리는 `NAIA_AGENT_WORKTREES_DIR` 로 알려 준다. 러너가 그 아래를
훑어 핀 커밋과 같고 깨끗한 것을 고른다. 없으면 **아무것도 돌리지 않고**
`prerequisites-missing` 으로 기록한다 — 준비가 안 된 것을 "돌렸는데 깨졌다" 로
남기면 다음 사람이 없는 버그를 찾는다.

## 3. 자기 몫을 확인한다

```
node scripts/run-regression.mjs --machine=<명단의 이름> --tier=deterministic_ci --dry-run
```

몫이 몇 개인지, 환경이 없어 건너뛸 스펙이 무엇인지, 공통 전제 중 빠진 것이
있는지를 말해 준다. 여기서 빠진 것을 채우고 나서 실제로 돌린다.

## 4. 돌리고 기록을 커밋한다

```
NAIA_AGENT_WORKTREES_DIR=<짝 워크트리 자리> \
NAIA_E2E_ARTIFACTS_DIR=<산출물 자리> \
  node scripts/run-regression.mjs --machine=<이름> --tier=deterministic_ci
```

끝나면 `docs/regression-runs/` 에 기록 하나가 생긴다. **커밋한다.** 커밋하지
않으면 다른 기계가 그것을 볼 수 없고, 전체가 덮였는지 판단할 수 없다.

자격증명이 있는 기계는 `--tier=deterministic_ci,credentialed_live` 로, 장치가
있는 기계는 `native_local` 까지 더해 돌린다. 명단에 적힌 능력 밖의 등급을
주면 러너가 이유와 함께 거절한다.

## 4-1. 실패 우선 루프 — 실패부터 잡고, 다 걷힌 뒤에 전체를 한 번

**실패가 나면 전체를 다시 돌리지 않는다.** 오너가 정한 순서는 이렇다.

```
전체 1회 → 실패 목록 → 실패만 재시험 → 고침 → 재시험 → … → 재시험 실패 0 → 전체 1회 확정
```

재시험은 이렇게 부른다.

```
node scripts/run-regression.mjs --machine=<이름> --only-failed
```

경로를 주지 않으면 `docs/regression-runs/` 에서 그 기계의 **가장 최근 기록**을
고른다. 재시험 기록도 후보라, 두 번째 재시험은 첫 재시험이 남긴 실패를 겨눈다.
특정 기록을 겨누려면 `--only-failed=docs/regression-runs/<파일>` 로 준다.

다시 도는 것은 두 부류다 — 돌았는데 통과 목록에 없는 것, 그리고 배정됐는데 아예
돌지 못한 것(묶음이 중간에 죽었거나 전제가 무너져 차례가 오지 않은 자리)이다.
두 번째를 빼면 "실패 0" 이 거짓이 된다. 요구 환경이 없어 건너뛴 스펙은 실패가
아니므로 다시 돌리지 않되 화면에는 이름이 남는다 — 사라지면 그 기계가 왜 그것을
영영 안 도는지 아무도 묻지 않게 된다.

왜 이렇게 바꿨나: 예전에는 실패 하나를 다시 확인하려면 그 기계의 몫 전부를
돌려야 했다. 자격증명 등급이면 쉰다섯 개, 한 시간이다. 고치고 확인하는 고리가
한 시간짜리면 사람은 확인을 미루거나 눈으로 때운다.

**재시험 기록은 전체를 대신하지 못한다.** 기록에 `kind: "retest"` 와 원 기록
이름(`retestOf`)이 붙고, `check-regression-complete.mjs` 는 그런 기록을 "전체
덮임" 판정에서 뺀다. 빼지 않으면 실패 셋만 다시 돌려 통과시킨 것으로 "다
덮였다" 가 되고, 실패 우선 고리가 곧 거짓 초록이 된다. 그래서 마지막 걸음이
**전체 1회 확정**이다 — 그 기록만이 덮임을 말할 수 있다.

러너가 다음 걸음을 스스로 찍는다. 재시험이 깨끗하면 `실패 0 — 이제 전체를 한 번
돌려 기록을 확정하라`, 아니면 남은 스펙 이름을 줄줄이 적는다.

### 도는 동안 무엇이 보이나

wdio 는 묶음이 끝날 때까지 조용한 편이라, 러너가 스펙 하나가 끝날 때마다 한 줄을
끼워 넣는다.

```
[regression] 12/41 ✓ 08-memory.spec.ts (41s)
[regression] 13/41 ✗ 21-cron-recurring.spec.ts (7s)
```

몇 번째인지와 어느 스펙이 오래 끄는지를 그 자리에서 볼 수 있다. 이 줄은 표시일
뿐 판정이 아니다 — 무엇이 통과했는지는 실행이 끝난 뒤 같은 출력을 다시 읽어
정한다.

## 5. 전체가 덮였는지 본다

```
node scripts/check-regression-complete.mjs --max-age-hours=24
```

기계마다 **가장 최근 실행 하나**만 본다. 오전에 실패하고 고쳐서 오후에 다시
돌렸다면 오후 것으로 판정한다 — 옛 실패가 창에 남아 계속 붉으면 사람이 곧
게이트를 무시하게 된다. 기록을 지워서 초록을 만드는 길은 열어 두지 않았다.
기록은 남기되 판정은 최신으로 한다.

## 채널에 알리기

러너가 만들어 준 `START`·`DONE` 줄을 채널에 올린다. **봇 토큰은 마스터
기계에만 두므로**, 합류하는 기계에 자격증명이 없는 것이 정상이다. 없다고
다른 봇 토큰으로 대신 쏘지 마라 — 다른 서버에 오발신된다.

줄을 사람이 복사해 붙이거나, 기록을 커밋해 두면 마스터가 읽어 대신 올린다.
자세한 것은 `CHANNEL.md` 의 "누가 채널에 쓰는가" 를 보라.

## 한 기계에서 하지 말 것

3층 회귀와 라이브 계약 테스트를 **동시에** 돌리지 않는다. 둘 다 herdr 터미널을
실제로 띄우는데 소유권 판정이 기계 단위라, 서로의 터미널을 "소유하지 않은
것" 으로 보고 거절한다. 실제로 회귀가 도는 중에 계약 테스트를 돌렸다가 열여섯
건이 무더기로 붉어졌고, 회귀가 끝난 뒤 같은 테스트가 그대로 통과했다.
